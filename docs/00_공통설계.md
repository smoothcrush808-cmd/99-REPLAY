## 1. 무엇을 만드나

나인구가 2024-09-29 ~ 12-06 카톡 「관점방」에서 **마지막 선물로 리딩한 기록**을,

**① 그의 관점 글을 시간순으로 읽고 ② 매매를 한 단계씩 리플레이**할 수 있는 GitHub Pages 사이트.

### 이 자료를 보는 눈 (브루스, 10-26)
- 나인구는 "리딩하면 내가 흔들려서 못 한다"고 줄곧 말했다. 다들 실력이 안 늘고 결과를 못 내자 **헤어지기 전 마지막 선물**로 리딩했다.
- 그래서 **이 시스템에 적응 못 해 흔들린 대목**이 있다 → 완전한 그의 매매로 보지 않는다.
- 그럼에도 **리스크 관리 · 불타기 · 매매 자리**를 가장 직관적으로 볼 수 있는 자료다.
- → 장부·차트 모두 「흔들림」을 지우거나 감추지 않는다. 그 자체가 재료다.

### 이 작업은 매매 볼트(BRUCE-TRADING)다
- 브루스의 분석·판단이 들어간다. **나인구 볼트(NAINGU-BRAIN-v2)에 쓰지 않는다.**
- 나인구의 글 자체를 P·E·C 노드로 뽑는 일은 **별도**(나인구 볼트 3군 세션). 이 설계와 섞지 않는다.

## 3. 시각 기준 (두 작업 공통 — 어기면 마커가 어긋난다)

- **모든 시각은 KST 벽시계.** 데이터 파일에는 **UTC epoch 초**로 저장하고, 화면에서 +9h 한다(BTC 심리차트 `app.js`의 `KST = 9*3600` 방식 그대로).
- 카톡 시각은 **분 단위**다. 메시지 시각 = 그 분의 1분봉 **시가**로 가격을 붙인다(규칙 고정, 장부 세션이 쓴다).
- 봉은 **봉 시작 시각** 기준(바이낸스와 같음).

## 4. 데이터 약속 (장부 → 차트)

장부 세션이 만들고, 차트 세션은 **읽기만** 한다. 형식을 바꾸려면 이 문서를 먼저 고친다.

### 4-1. `posts.json` — 관점방 메시지 전부 (관점 읽기용)
```json
[{"id":"p0001","t":1728262800,"text":"숏","kind":"signal","trade":"T012","photo":false}]
```
- `t` UTC epoch 초 · `text` **원문 그대로**(고치지 않는다, 줄바꿈 유지) · `kind` ∈ `signal`(진입·청산 신호) · `risk`(스탑·비중·정리) · `view`(관점·사고과정) · `routine`(출근·퇴근·착석 등) · `chat`(나머지)
- `trade` 그 메시지가 속한 매매 id(없으면 null) · `photo` 사진 메시지면 true
- **나인구 메시지만** 넣는다. 다른 사람 4줄(입장·질문)은 빼거나 `kind:"chat"`에 이름 없이 — **실명 노출 금지**(§6).

### 4-2. `trades.json` — 복원한 매매 (리플레이·마커용)
```json
[{"id":"T012","side":"short","open":1728262800,"close":1728275400,"status":"closed",
  "events":[
    {"t":1728262800,"type":"entry","price":64210.5,"post":"p0412"},
    {"t":1728262980,"type":"stop","stop":65500,"post":"p0413"},
    {"t":1728266340,"type":"stop","stop":64689,"post":"p0414"},
    {"t":1728268980,"type":"reduce","pct":60,"price":63880.1,"post":"p0418"},
    {"t":1728269100,"type":"stop","stop":63910,"note":"리스크 0%","post":"p0419"},
    {"t":1728275400,"type":"exit","price":63650.0,"post":"p0425"}],
  "flags":["흔들림?"],"confidence":"high"}]
```
- `type` ∈ `entry` · `add`(불타기/추가) · `reduce`(분할 정리, `pct`) · `stop`(스탑 설정·이동, `stop`) · `tp`(익절가 예약) · `exit`(종료·풀익절·손절)
- `price` 장부 세션이 1분봉에서 붙인 값. 그가 가격을 직접 적었으면 `quoted` 칸에 그 숫자를 따로 둔다(둘을 섞지 않는다).
- `confidence` ∈ `high`(신호가 분명) · `low`(묶음이 애매 — 브루스 확인 대상)
- `flags` 브루스·장부 세션이 붙이는 꼬리표(예: `흔들림?` · `정정` · `마지막 도전`). **판정이 아니라 표시**.

### 4-3. 사람용 원본
- `장부.csv` — 사건 한 줄씩(위 events를 펼친 것). 브루스가 엑셀로 열어 고친다. **CSV가 정본, JSON은 CSV에서 다시 만든다.**

## 6. ★공개 범위 — **A안 결정 (2026-10-26 브루스)**: 글·장부는 비밀번호 암호화로만 올린다

GitHub Pages는 **누구나 볼 수 있는 공개 사이트**다(지금 BTC 심리차트도 그렇다).
- 시세(봉)는 공개 데이터라 문제없다.
- **관점방 글은 나인구가 유료/비공개 방에서 쓴 글**이다. 그대로 올리면 인터넷에 공개된다.

| 안 | 방법 | 장단 |
|---|---|---|
| **A (추천)** | `posts.json`·`trades.json`을 **비밀번호로 암호화**해서 올린다(브라우저에서 AES-GCM 복호화, 비번은 처음 한 번 입력 → 기기에 기억) | 폰에서도 링크 하나로 열림. 저장소·사이트에는 암호문만 |
| B | 글·장부는 올리지 않고, 페이지의 「가져오기」로 기기마다 파일을 넣는다 | 가장 안전. 기기 옮길 때마다 파일 필요 |
| C | 그대로 공개 | 가장 단순. 나인구 글이 공개됨 |

→ **A로 간다(10-26 결정).** 평문 `posts.json`·`trades.json`은 저장소에 절대 올리지 않는다(`.gitignore`). 비번 입력 화면만 끄면 B(가져오기)로도 쓸 수 있게 만든다.
- 어떤 안이든 **다른 참여자 실명은 넣지 않는다.**

## 7-1. ★차트는 클라우드 세션(claude.ai/code)으로 만든다 (2026-10-26 결정)

- 클라우드 세션은 **GitHub 저장소를 복제해 그 안에서** 일한다. 이 컴퓨터(`D:\99\…`)의 파일은 **못 본다.**
- 그래서 **차트의 집은 매매 볼트가 아니라 GitHub 저장소**다. 매매 볼트의 `관점방\site\`는 그 저장소를 **`git clone`한 사본**이다
  → 클라우드에서 큰 틀을 만들어 배포한 뒤, 세부 작업을 로컬(매매 볼트 세션)에서 할 때는 `git pull` → 고치고 → `git push`. 같은 저장소라 「옮겨 오는」 일이 없다.
- 클라우드 세션에 필요한 것은 **저장소 안에** 있어야 한다:
  - 이 설계 문서 3개 → 저장소 `docs/`에 복사해 둔다(정본은 여기 매매 볼트, 바뀌면 다시 복사).
  - BTC 심리차트 원본 → 클라우드가 `https://smoothcrush808-cmd.github.io/BTC/`에서 직접 받는다(인터넷 됨).
  - 1분봉 → 클라우드가 data.binance.vision에서 직접 받는다.
  - **관점방 글·장부는 클라우드에 주지 않는다**(원문은 이 컴퓨터에만). 클라우드는 §4 형식의 **가짜 샘플**(`docs/sample_posts.json` · `docs/sample_trades.json`, 메시지 몇 개)로 화면을 만든다.
    진짜 데이터는 장부 세션(로컬)이 만든 뒤 **암호화 파일(`data/*.enc`)로만** 저장소에 올린다(§6 A안). 이러면 저장소를 공개로 둬도 원문이 새지 않는다.
- 장부 세션은 **로컬(매매 볼트)** 그대로 — 원문 파일이 이 컴퓨터에 있다.

## 9. 지키는 것

- **나인구의 글은 원문 그대로.** 요약·교정·해석을 원문 칸에 넣지 않는다. 해석은 `flags`·`note`·브루스 메모로 따로.
- 장부의 「판정」(흔들렸다·실수였다)은 **브루스가** 한다. 세션은 후보만 표시한다.
- 시세 숫자는 아카이브에서 뽑은 값만. 눈대중 금지.
