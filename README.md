# 99-REPLAY — 관점방 리플레이

나인구 「관점방」(2024-09-29 ~ 12-06) 리딩 기록을 BTC 심리차트 위에서 **읽고 · 리플레이**하는 페이지.
원본 차트: https://smoothcrush808-cmd.github.io/BTC/ (저장소 `smoothcrush808-cmd/BTC` — 건드리지 않는다)

## 처음 여는 세션(클라우드)은 여기부터

1. `docs/00_공통설계.md` — 전체 틀·데이터 형식·시각 기준·공개 범위(**A안: 글·장부는 암호화본만**)

3. `docs/sample_posts.json` · `docs/sample_trades.json` — **가짜 샘플**로 화면을 만든다
   - 글은 전부 지어낸 `[샘플]` 문장이다(나인구 원문 아님). 가격만 실제 2024-10-15·16 BTCUSDT 1분봉 시가라 마커가 봉 위에 앉는다.
   - 일부러 넣은 경우: 줄바꿈 있는 글 · 사진 메시지 · 정정(reduce 덮어쓰기, `corrected_by`) · 계획(`plans`) · 불타기(`add`) · 「리스크 0%」 스탑 · 종료 없이 다음 진입(`unclosed`, `confidence: low`) · flags.
   - 진짜 데이터는 로컬 장부 세션이 만들어 `data/posts.enc` · `data/trades.enc`(암호화)로만 들어온다.

`docs/01_장부_작업지시.md`는 로컬 장부 세션용이다(참고만).
설계 문서의 정본은 브루스 PC의 매매 볼트(`BRUCE-TRADING\관점방\설계\`)다 — 바뀌면 여기로 다시 복사한다.

## 빌드 명령 (저장소 루트 = 매매 볼트 `관점방\site\`)

### 1) 시세 — `python tools/build_klines.py`
- data.binance.vision 현물 `BTCUSDT` 1분봉: 월간 2022-01 ~ 2024-11 + 일간 2021-12-31(KST 1월 1일 0시 = UTC 12-31 15시) · 2024-12-01 ~ 06.
- zip 캐시: 기본 `..\_cache`(= `관점방\_cache`, 장부 세션과 공유). 없으면 `.\_cache`. `--cache 경로`로 바꿀 수 있다. 받을 때 바이낸스 `.CHECKSUM`(sha256)으로 확인.
- 이미 받은 zip만으로: `--no-download`.
- 출력 `data/klines/{1m,5m,15m,1h}/YYYY-MM.bin` + `index.json`. 범위 2022-01-01 00:00 ~ 2024-12-06 23:59 **KST**.
  - 월 파일은 **KST 달** 기준. 상위 간격은 1분봉을 UTC 경계로 합친다(바이낸스 봉과 같음).
  - 형식: 봉마다 `int32` little-endian 5개 = 20바이트 — `t`(분 단위 UTC epoch, 봉 시작) · `o h l c`(가격 ×100 정수). 가격을 정수로 둬서 소수 둘째 자리까지 그대로다.
  - 시각 자릿수로 초/밀리초/마이크로초를 판별한다(2025년부터 아카이브가 µs로 바뀐 적 있음).
  - 바이낸스 점검 등으로 빈 분은 **채우지 않고** 실행 끝에 목록만 보여준다.
- 1분봉 한 달 ≈ 0.9MB, 전부 합쳐 약 40MB. 페이지는 보이는 달 근처만 늦게 읽고, 1분봉은 메모리에 3달(보이는 달 ±1)만 둔다.

### 2) 글·장부 암호화 (A안) — `python tools/encrypt_data.py`
- 장부 세션이 만든 `posts.json` · `trades.json`을 `data/`에 두거나 `--src 폴더`로 지정 → `data/posts.enc` · `data/trades.enc`.
- PBKDF2-HMAC-SHA256(310,000회) → AES-256-GCM. 두 파일이 같은 salt를 써서 브라우저는 키를 한 번만 만든다.
- **비밀번호는 실행할 때 입력만 한다.** 저장소·코드·문서 어디에도 쓰지 않는다. `--check`로 다시 풀리는지 확인.
- 올리기 전 `git status`로 평문 `.json`이 안 보이는지 확인(`.gitignore`가 막는다).
- 페이지: 첫 방문에 비밀번호 → 브라우저 안에서만 푼다. 「이 기기에서 기억」을 고르면 다음부터 안 묻는다. 틀리면 차트만 보인다.
- **B안**(암호 파일 없음): 패널의 「파일 가져오기」로 기기마다 `posts.json`·`trades.json`을 넣는다(이 기기 브라우저에만 저장).
- 개발·확인용: 주소 뒤에 `?sample=1` → `docs/sample_*.json`(가짜)로 연다.

## 쓰는 법

원본 BTC 심리차트의 쓰는 법(그리기·지우기·되돌리기·북마크·와이드·홈 화면 추가)은 그대로다. 달라진 것만:

| 동작 | 방법 |
|---|---|
| 봉 간격 | 1분 / 5분 / 15분 / 1시간 (키 `1` `2` `3` `4`) |
| 최신으로 | 2024-12-06 마지막 봉 (키 `L`). 리플레이 중엔 「여기까지」 |
| 관점 패널 | PC: 오른쪽 (켜기/끄기 `O`) · 폰 세로: 아래 서랍(「관점방」 탭) · 와이드: 오른쪽 |
| 글 → 차트 | 글을 탭하면 차트가 그 시각으로 가고 세로 점선. 「따라가기」를 켜 두면 차트를 움직일 때 패널이 그 시각 근처 글로 따라온다 |
| 필터 · 검색 | 전부 / 관점(view) / 신호·리스크(signal·risk) · 본문 글자 검색 |
| 매매 마커 | 진입 ▲(롱 초록)/▼(숏 빨강) · 추가 ＋ · 분할 정리 ●(비율) · 종료 ✕ · 스탑 계단(주황 → 「리스크 0%」 칸부터 하늘색). 1시간봉에선 진입·종료만. 켜기/끄기: 도구 줄 「매매」(`M`) |
| 마커 탭 | 그 매매의 원문 카드 + 요약(진입가·첫 스탑 거리·보유 시간·MFE/MAE·결과 %) |
| 리플레이 | 상단 「리플레이」(`P`) → 매매 고르기 → 블라인드 시작 |

- 「리스크 0%」 칸: 그 스탑 사건 `note`에 「리스크 0%」가 있거나, 스탑이 **첫 진입가**를 넘어 수익 쪽에 있을 때 그 칸부터 색이 바뀐다.
- 결과 %·MFE/MAE는 **첫 진입가 기준**(불타기·분할 정리의 비중 가중은 하지 않는다 — 비중 숫자가 장부에 없어서). MFE/MAE는 진입 분 ~ 종료 분의 1분봉 고가·저가.
- 정정된 사건(`corrected_by`)은 지우지 않고 흐리게 「정정됨」으로 남긴다.

### 리플레이
1. **블라인드**: 진입 시각 전에 닫힌 봉까지만 보인다. 그 뒤 봉·마커·글은 숨김. 화면에 「여기까지」 세로선.
2. 시작하면 「나라면?」이 열린다 — 들어갈까(들어간다/안 들어간다) · 방향 · 스탑 자리(「차트에서 찍기」 → 가격 탭) · 한 줄 메모 → 저장.
3. 「▶▶ 다음 사건」(`Shift+→`, `N`) → 그의 실제 사건 하나가 원문과 함께 열리고, 그 시각까지 봉이 늘어난다.
4. 사건마다 다시 「나라면?」(유지 · 스탑 이동 · 일부 정리 · 추가 · 익절 예약 · 종료).
5. 끝나면 「나란히 보기」 — 그의 전 과정(원문)과 내 판단. 「같음/다름」은 **같은 행동인가**만 표시(잘잘못 판정 없음). 진입은 「들어간다 + 같은 방향」이면 같음.
- 「▶ 1봉」(`→`) · 「⏵ 자동」(`Space`, 1~20봉/초)도 된다. 둘 다 그의 다음 사건 시각에서 멈춘다(먼저 적을 수 있게).
- 「블라인드」 버튼을 끄면 전체 보기(공부용).

## 리플레이 답 · 내보내기 형식

- 브라우저 저장 키: `nine9Replay.answers.v1` (그림 `nine9Replay.drawings.v1` · 북마크 `.bookmarks.v1` · 설정 `.prefs.v1`).
  원본 BTC 심리차트(`psychChart.*`)와 같은 github.io 주소라 저장소를 같이 쓰므로 **키 이름을 달리했다** — 서로 덮어쓰지 않는다.
  그래서 원본 차트의 그림은 자동으로 안 보인다. 필요하면 원본에서 내보내기 → 여기서 가져오기(그림 형식이 같다).
- 「저장」 → 내보내기 = 그림 + 북마크 + 리플레이 답을 JSON 하나로. 가져오기는 합치기(같은 칸은 나중에 적은 답이 남는다).

```jsonc
{
  "app": "99-replay", "version": 1, "symbol": "BTCUSDT",
  "exportedAt": "2026-10-26T05:00:00.000Z",
  "drawings": [ /* 원본 BTC 심리차트와 같은 그림 형식 */ ],
  "bookmarks": [ /* { id, name, t(ms), iv, w } */ ],
  "replay": {
    "key": "nine9Replay.answers.v1",
    "answers": {
      "T012": {                       // 매매 id (trades.json의 id)
        "trade": "T012", "side": "short",
        "open": 1728262800,           // 그 매매 첫 사건 시각 (UTC 초)
        "updatedAt": "2026-10-26T05:00:00.000Z",
        "steps": {
          "0": {                      // 그의 0번째 사건(진입)을 열기 직전에 적은 판단
            "act": "enter",           // 0번: enter | skip
            "side": "short",          // act=enter일 때만
            "stop": 65500,            // 차트에서 찍은 스탑 (없을 수 있음)
            "memo": "박스 상단 실패",   // 한 줄 메모 (없을 수 있음)
            "now": 1728262800,        // 적을 때 보이던 마지막 시각(「여기까지」, UTC 초)
            "iv": "1m",               // 적을 때 보던 봉 간격
            "at": "2026-10-26T05:00:00.000Z"
          },
          "3": { "act": "reduce", "now": 1728268980, "iv": "1m", "at": "…" }
          // 1번 이후: hold(유지) | stop(스탑 이동) | reduce(일부 정리) | add(추가) | tp(익절 예약) | exit(종료)
        }
      }
    }
  }
}
```
- 단계 번호 `i` = trades.json의 그 매매 `events`를 **시각순으로 정렬했을 때** i번째 사건 바로 앞. 사건과 짝짓기: `act`가 사건 `type`과 같으면(entry↔enter) 「같은 행동」.
- 매매 볼트 `복기\`·`gaze training\`에서 쓸 때: `answers`를 매매 id로 장부.csv와 이어 붙이면 된다.

## 데이터 갱신 방법
- **장부가 바뀌면**: 장부 세션이 `장부.csv` → `posts.json`·`trades.json` 다시 만들기 → `python tools/encrypt_data.py --src ..\장부` → `git add data/*.enc` → push.
- **시세는 고정**(2024-12-06까지)이라 다시 만들 일이 거의 없다. 형식을 바꿀 때만 `build_klines.py` 다시.
- 배포 직후 옛 파일이 보이면: `index.html`의 `app.js?v=` 숫자를 올린다(시세 파일은 `index.json`의 `built` 시각이 주소에 붙어 자동으로 새로 받는다).
